# L5 SPARQL：五种查询模式

## 概念

SPARQL 是图谱世界的 SQL，但思维模型不同：**不是"查表"，是"图模式匹配"**——
你画出子图的形状（`?s a :SKU ; :price ?p`），引擎找出所有能匹配上的子图。

本课五个文件对应五种最常用的模式。全部用 Jena `arq` 跑：

```bash
export PATH="/opt/homebrew/opt/openjdk/bin:$PATH"
cd ontology-demo/tutorial/L5_sparql
arq --data data.ttl --query q1_filter.rq
```

## 五个模式与预期输出

**Q1 FILTER（条件过滤）**——价格 300~600 且销量过百：

```
----------------------------
| name     | price   | sales |
============================
| "闪电跑鞋" | 499.00 | 120   |
----------------------------
```

**Q2 OPTIONAL（可选匹配，= SQL 的 LEFT JOIN）**——没品牌的白牌鞋也要出现在结果里；
注意 `:madeBy/:country` 这个**属性路径**写法，斜杠 = 顺着边多走一跳：

```
--------------------
| name   | country |
====================
| "山野越野" | "中国"    |
| "清风跑鞋" | "中国"    |
| "白牌跑鞋" |         |   ← OPTIONAL 的价值：缺数据不丢行
| "竞速碳板" | "美国"    |
| "闪电跑鞋" | "美国"    |
--------------------
```

**Q3 聚合（GROUP BY）**——每个类目的 SKU 数和总销量：

```
----------------------------------------------
| cat                | skuCount | totalSales |
==============================================
| :cat_running_shoes | 4        | 455        |
| :cat_trail_shoes   | 1        | 80         |
----------------------------------------------
```

**Q4 属性路径 `*`（传递闭包）**——"运动户外大类下所有 SKU"。
`:subCategoryOf*` 表示"沿这条边走零到任意多跳"，一行覆盖任意深的类目树：

```
----------
| name   |
==========
| "清风跑鞋" |
| "闪电跑鞋" |
| "白牌跑鞋" |
| "山野越野" |   ← 越野鞋挂在 trail_shoes 下，照样被"运动户外"收编
| "竞速碳板" |
----------
```

**Q5 CONSTRUCT（查询结果即新三元组）**——把"月销>100"物化成 `:HotSeller` 类型：

```
@prefix : <https://demo.local/ecat#> .
:sku1  a  :HotSeller .
:sku3  a  :HotSeller .
```

## 观察点

1. **属性路径是 SPARQL 的超能力**：`*`（零到多）、`+`（一到多）、`/`（串联）、`|`（或）。
   SQL 里递归 CTE 才能写的树遍历，这里三个字符。
2. **CONSTRUCT 让查询结果回流成知识**——这是"规则打标"的标准做法：
   跑一次 Q5，把结果合并回图里，下次直接查 `?s a :HotSeller`。
3. 注意 Q4 的答案和 L3 传递性推理的结果一样——**同一件事，推理（物化）和查询（即时）
   两条路都能到**。生产选型就看哪个：高频查询用物化，长尾临时查询用属性路径。

## 练习

1. 用 `+` 代替 `*` 重写 Q4，结果差在哪？（`*` 含自身，`+` 至少走一跳）
2. 写一条查询：找出"同品牌下有销量>100 的热销品"的所有品牌及其热销品。
3. 把 Q5 的结果保存：`arq --data data.ttl --query q5_construct.rq --output ttl > hot.ttl`，
   然后 `arq --data data.ttl --data hot.ttl --query ...` 查询 `:HotSeller`——体会
   "多文件合并成一张图"是 RDF 的常态操作。
